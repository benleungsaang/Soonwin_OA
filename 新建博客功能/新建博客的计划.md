# 博客功能实现计划

## Context

在 Soonwin OA 系统中新增"微博客"功能模块。当前系统已有完善的前后端架构（Vue 3 + Flask + SQLAlchemy），以及可复用的媒体上传组件（`ImageUploadPreview.vue`）和视频处理队列（`ProcessingQueue`）。需要将参考的独立博客应用（`posts.html` + `posts_api.py`）适配集成到现有系统中，并新增编辑历史、草稿、软删除等功能。

---

## 实施步骤

### 第 1 步：后端 — 数据库模型

**新建文件：** `soonwin-os-Python-Server/app/models/blog.py`

创建 5 个模型（均继承 `db.Model`，含 `to_dict()` 方法）：

| 模型 | 表名 | 核心字段 |
|------|------|----------|
| `BlogPost` | `blog_post` | id, content, author, author_id, is_draft, is_deleted, repost_from, edit_version, search_field, created_at, updated_at, deleted_at, deleted_by |
| `BlogMedia` | `blog_media` | id, post_id(FK), media_type, file_path, thumbnail_path, original_filename, file_size, width, height, duration, compress_status, created_at |
| `BlogEditHistory` | `blog_edit_history` | id, post_id(FK), version, content, media_snapshot(JSON), created_at, edited_by |
| `BlogComment` | `blog_comment` | id, post_id(FK), author, author_id, content, created_at, is_deleted |
| `BlogLike` | `blog_like` | id, post_id(FK), user_id, created_at (UNIQUE(post_id, user_id)) |

**修改文件：** `soonwin-os-Python-Server/app/__init__.py`
- 在 `with app.app_context():` 块内导入博客模型
- 注册博客蓝图并设置应用实例

### 第 2 步：后端 — 权限常量

**修改文件：** `soonwin-os-Python-Server/app/constants/simple_permission_constants.py`
- 添加 `ROUTE_BLOG_MANAGE = "blog_manage"`（全体共有权限）

### 第 3 步：后端 — API 路由

**新建文件：** `soonwin-os-Python-Server/app/routes/blog_routes.py`

蓝图 `blog_bp`，URL 前缀 `/api`，使用 `@route_permission(ROUTE_BLOG)` 装饰器。

**API 端点设计：**

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/posts` | 全体 | 获取已发布博文列表（分页+搜索） |
| GET | `/api/posts/draft` | 登录 | 获取当前用户草稿 |
| POST | `/api/posts/draft` | 登录 | 保存/替换草稿 |
| DELETE | `/api/posts/draft` | 登录 | 删除草稿 |
| POST | `/api/posts` | 全体 | 创建博文（FormData: content + media[]） |
| GET | `/api/posts/<id>` | 全体 | 获取单篇博文详情 |
| PUT | `/api/posts/<id>` | 全体 | 更新博文（自动保存编辑历史） |
| PUT | `/api/posts/<id>/publish` | 登录 | 发布草稿为正式博文 |
| DELETE | `/api/posts/<id>` | 全体 | 软删除博文（仅拥有者/管理员） |
| GET | `/api/posts/deleted` | 管理员 | 查看已删除博文列表 |
| PUT | `/api/posts/<id>/restore` | 管理员 | 恢复已删除博文 |
| DELETE | `/api/posts/permanent-delete` | 管理员 | 彻底删除（含物理文件） |
| GET | `/api/posts/<id>/history` | 管理员 | 获取编辑历史列表 |
| GET | `/api/posts/<id>/history/<ver>` | 管理员 | 获取特定版本完整数据 |
| GET | `/api/posts/<id>/comments` | 全体 | 获取留言列表 |
| POST | `/api/posts/<id>/comments` | 登录 | 添加留言 |
| DELETE | `/api/posts/<id>/comments/<cid>` | 全体 | 删除留言 |
| POST | `/api/posts/<id>/like` | 登录 | 切换点赞状态 |
| GET | `/api/posts/media/<path>` | 全体 | 提供媒体文件 |
| POST | `/api/posts/media/upload` | 全体 | 单独上传媒体文件 |

**关键实现逻辑：**

1. **媒体存储路径：** `assets/PostsMedia/<YYYY>/<MM>/<DD>/`（复用 `save_uploaded_file` + `get_date_dir`）
2. **视频转码：** 保存视频后调用 `add_video_compress_task()` 加入 `ProcessingQueue`，异步执行 ffmpeg 转码（MOV/H.265 → MP4/H.264）。转码完成后更新 `BlogMedia.file_path` 指向压缩文件，状态设为 `success`；失败则设为 `failed`
3. **编辑历史：** `update_post()` 中先将当前 content + 媒体快照（JSON）存入 `BlogEditHistory`，再更新博文并递增 `edit_version`
4. **草稿：** `is_draft=1` 的博文，每用户仅一条。保存草稿时查找已有草稿并替换；发布时设置 `is_draft=0` 和 `created_at=now`
5. **软删除：** 设置 `is_deleted=1` + `deleted_at` + `deleted_by`，不删除物理文件；彻底删除时删除物理文件+所有关联记录
6. **响应格式：** 统一使用 `{success: bool, data: ..., message: ...}`

## 验证方案

1. **启动后端（开发模式）：** `python run.py`（端口 5001）
2. **启动前端（开发模式）：** `yarn dev`（端口 5173）
3. **功能测试清单：**
   - 创建博文（含文字+图片+视频）
   - 视频上传后查看"转码中"状态，等待转码完成后刷新确认可播放
   - 编辑博文，确认旧版本存入编辑历史
   - 管理员查看编辑历史，展示所有版本
   - 保存草稿，关闭页面再打开确认草稿存在
   - 发布草稿，确认草稿清空
   - 删除博文，管理员在回收站查看
   - 管理员恢复博文 / 彻底删除博文
   - 留言添加和删除
   - 点赞切换
   - 搜索博文内容
   - 分页加载
4. **权限验证：** 非管理员看不到编辑历史和回收站入口
5. **数据库验证：** 检查 `blog_edit_history` 表是否正确记录每次编辑
